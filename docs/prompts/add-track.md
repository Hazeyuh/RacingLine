# 给 Agent 的赛道接入 Prompt

复制下面整段，附上图片或手绘文件，并填写方括号。Agent 应在 RacingLine 项目内工作；不知道的项目写“不确定”。

```text
请在当前 RacingLine 项目中添加赛道，完成可复现的输入、构建和验证。
先阅读 README.md、docs/add-track.md、tracks/templates/tablet-trace.json 和 tools/import_track.py，遵守项目约定。保持现有卡丁车动力学，不为掩盖几何问题更改功率或抓地力。

我的输入：
- 类型：[真实赛道图 / 卫星图加清晰示意图 / 数位板手绘中心线 / 数位板手绘内外边界]
- 名称与新 id：[名称；如 my-design-v1]
- 文件：[附图或本地路径，注明哪张用于描点]
- 已知长度与依据：[例如比例尺 20 m 或实测直道 100 m]
- 中心线设计的道路总宽：[例如 8 m；边界画法写按边界确定]
- 行驶方向和起终点：[箭头、标记或文字说明]
- 路肩和排除区：[可用路肩；维修区、墙体、轮胎区不纳入]
- 手绘图层／颜色：[中心线、内外边界、比例尺；笔触粗细不代表道路宽度]

请执行：
1. 查看图像或矢量路径，记录尺寸和来源，区分道路、路肩、文字、墙体、维修通道和中心岛。没有可靠长度时向我索取一个长度，不猜比例。缺少关键方向或边界规则时，只询问影响转换的项目。
2. 手绘图按我指定的尺寸定标。中心线画法按指定米制宽度生成道路；边界画法提取外圈和中心岛，再选择道路内平滑参考线。保留我的布局，不替换成模板椭圆。笔压和笔触粗细不当成高程或宽度。无法解释的交叉口或透视问题先说明，不擅自补画。
3. 两图传递比例时保存同位置测量端点、计算式和依据；最终 calibration.points_px 属于实际描点图。检查裁剪、缩放和纵横比例。
4. 写 trace.json，点坐标来自实际图像或矢量路径，中心线按行驶顺序排列，第一点为起终点。记录标定、路肩规则、不确定位置和处理方法；必要时另写 provenance.md。输入先放 runs/track-input-<id>/，不要提前占用注册目录。
5. 使用 import_track.py --check 生成并查看 geometry-overlay.png，检查闭环、自交、比例、弯心突出、平滑过冲、窄颈和车宽走廊。错误先修描点；重要边界存在不同合理解释时给我叠加图确认。
6. 规则明确、预览正确后注册新 id，不覆盖旧赛道；保存源 JSON 和完整构建命令。重启后台并确认网页能选到新赛道。若有我的求解运行或暂停，不终止它，等完成或明确报告尚未重启。注册后将原图移入 tracks/<id>/source-assets/。
7. 运行 500 点原生卡丁车求解，检查成功退出、时间严格递增和完整闭合赛车线在车宽走廊内；必要时用 1000 点比较。保存脚本版本与验证结果，区分几何通过和动力学通过。
8. 最后给我预览、关键尺寸、标定依据、重建命令、验证结果和网页赛道名称。原始第三方图片不默认公开。本任务不要求发布 Git 或更改车辆模型。
```
