# 本地入口与赛道接入

项目提供统一后台入口，以及“图片／数位板手绘 → Agent 描点 → JSON → 通用构建脚本 → 原生验证”的流程。下文介绍后台开关、图像准备、手绘约定和重建命令；可直接复制 [Agent prompt](prompts/add-track.md)，附上自己的图像。

## 启动、打开网页与停止

首次安装运行 `./tools/setup.sh`。之后在项目根目录执行：

```sh
./racingline                 # 启动后台并自动打开默认浏览器
./racingline start           # 同上；重复执行不会重复启动
./racingline status          # 查看 PID、项目路径和当前求解 ID
./racingline open            # 再次打开网页
./racingline stop            # 停止后台
./racingline restart         # 重启并打开网页，加载新增赛道
```

macOS 可在 Finder 双击 `RacingLine.command`，使用启动／停止／状态／重启菜单。关闭网页或终端不会停止后台。脚本不自动安装或编译依赖，初次安装仍需 setup。

默认端口 8765，所有命令可加 `--port 8766`，启动和重启可加 `--no-open`。运行信息和日志保存于 `runs/server-<端口>.json` 和 `.log`。脚本通过健康接口核对项目路径与实际 PID，不按端口任意杀进程；旧版前台进程占用端口时，先退出旧进程或换端口。

有运行或暂停中的求解时，普通停止／重启会拒绝操作。确需中断，用 `./racingline stop --force`，实验将标记为中断失败，输入和日志保留。页面的“暂停求解”只暂停优化器，不关闭后台。原 `tools/start.sh` 保留为前台调试入口。

## 准备真实赛道图片

使用俯视图、带比例尺卫星图或平面 CAD 导出图，提供至少一个已知长度，例如比例尺或实测直道长度。普通斜视照片、视频画面不能直接套用全图统一比例；透视问题应先处理，不能让 Agent 凭娱乐卡丁车通常多宽猜尺寸。

卫星图有比例尺而赛道示意图边界更清楚时，可以在两图测同位置、同一对道路边缘的宽度，把米制宽度传递到清晰图。保存两图端点与计算过程；最终标定端点必须属于实际用于描点的图像。确认行驶方向、起终点、路肩是否可用，以及维修区／支路的排除规则。

## 用数位板自行设计

固定画布，画平面俯视赛道，推荐两种方式：

| 画法 | 需要提供 | 转换方式 |
|---|---|---|
| 单条闭合中心线 | 道路总宽、比例尺、方向和起终点 | 按指定米制宽度扩成道路；笔触粗细不代表路宽 |
| 内外两条闭合边界 | 比例尺、方向和起终点 | Agent 分别描边，并选道路内的参考线；支持变化路宽 |

在独立图层画标明长度的比例尺，例如“20 m”，建议长度至少约 100 px；也可用软件中的矢量尺寸。设计尺寸由你决定，不需要卫星图。方向箭头、起终点和文字单独放一层，线条颜色容易区分。笔压不作为高程、抓地力或道路宽度。保留原始分层文件，导出 PNG 或 SVG，告诉 Agent 画布尺寸和图层含义。

避免尖角、交叉笔画和过窄路段，给相邻赛道留间距。当前模型支持一个内侧岛的单一平面闭环，不支持八字交叉、立交、多分支、开放路线或高程。不能把交叉点擅自补成弯道。不要在描点后裁剪或非等比拉伸，再沿用旧坐标。SVG 由 Agent 转成描点 JSON；当前导入脚本不直接解析 SVG。

## 可复现输入与命令

完整输入例子是 `tracks/templates/tablet-trace.json`。模板是演示椭圆，不是你的实际设计；复制后更换 id 和点集。坐标采用原图像素，x 向右、y 向下，中心线点按行驶顺序排列，第一点定义起终点，末尾不用重复首点。

必要字段为 `id`、`name`、`kind`（design 或 image）、`source`、`image_size`、`direction`、`calibration.points_px`、`calibration.length_m` 与 `centerline_px`。中心线画法还需 `road_width_m`；边界画法提供 `outer_boundary_px` 和 `inner_boundary_px`，分别表示最外圈和中心岛，不是行驶方向的左／右边界。还可填写 `kerb_policy` 和 `vehicle_width_m`。

参考线不是最优赛车线，只为车辆位置和道路宽度提供平滑坐标。Agent 的描点必须来自实际像素或矢量路径，不能凭文字编造一组看似合理的坐标。

先生成预览，不注册：

```sh
.venv/bin/python tools/import_track.py path/to/trace.json --check --image path/to/track.png
```

输出到 `runs/track-preview-<id>/`，包括原图叠加预览、几何、XML、元数据和检查结果；没有图片时省略 `--image`，生成纯几何图。查看弯心突出、路肩误判、平滑过冲和窄颈。脚本检查闭环、自交、内外边界包含关系、参考线、车宽走廊和曲率坐标折叠，不以删约束修复错误。

几何确认后，用同一份 JSON 注册：

```sh
.venv/bin/python tools/import_track.py path/to/trace.json --image path/to/track.png
./racingline restart
```

生成 `tracks/<id>/trace.json`、`geometry.json`、`<id>.xml`、`metadata.json`、`validation.json` 与 `geometry-overlay.png`，后台重启后自动发现，无需改赛道枚举。已有 id 不覆盖，修订用新 id 保留旧实验版本。注册前不要自行创建目标目录；输入暂放 `runs/track-input-<id>/`，注册后再将原图移入 `tracks/<id>/source-assets/`。

source-assets 目录与叠加图片默认不进 Git。新赛道当前用生成的叠加图核对，网页显示数值道路和赛车线；在线原图叠加仍仅用于南京。自定义赛道车宽与南京使用同一约束流程。

进入网页运行 200cc 参考、500 点求解，检查原生成功退出、时间严格递增和闭合赛车线在车宽走廊内；必要时再用 1000 点检查网格差异。几何检查通过不等于动力学验证通过。保留原图、标定依据、trace.json、脚本版本、命令和验证结果；复现依赖保存的 JSON，不需要再让 AI 猜一次边界。附带“手绘模板 · 椭圆”已完成 500 点原生验证，只用于熟悉流程。
