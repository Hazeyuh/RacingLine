# 基础模型示例

当前示例用于验证 Fastest-lap 默认 kart-6dof 模型，使用上游 Vendrell 闭环赛道。输入是实验名称与网格点数；车辆配置取自 `database/vehicles/kart/roberto-lot-kart-2016.xml`。现已支持基于此模型修改最大功率与总质量；视频校准暂缓。

网页通过本地 Python HTTP 服务启动独立求解进程。每次实验保存 `config.json`、完整 `solver.log`、`vehicle.xml`、上游 `solution.xml`、结果 `result.json` 和状态 `status.json`。C++ 异常或进程退出会记录为失败。使用伪终端读取原生输出，便于实时展示 IPOPT 迭代，不生成模拟迭代数据。

结果展示赛车线、速度着色、转向、后轴控制、时间回放与实验比较。累计 delta 在相同参考线弧长处比较时间，以线性插值对齐不同网格，并补上闭环最后一段；定义为当前减基准。不同网格造成的圈速差异用于检查离散化稳定性，不等同于车辆升级或驾驶改善。

迭代图读取 IPOPT 输出的目标值和约束误差。迭代中的目标值不一定是可行圈速；目标变化与实验圈速 delta 分开显示。当前 C API 没有导出每轮轨迹，最终赛车线回放已接入，逐轮赛车线回放尚未接入。

南京赛道页保留原始图片，支持三组两点标定。比例尺为 25 m；卫星图尺度乘主直道像素宽度，再除以清晰图同位置像素宽度，得到清晰图尺度。初始宽度端点为目视草稿，存储原始端点与状态，不把它用于圈速结果。边界、可压路肩、维修区排除与比赛路径核对仍需后续完成。

## 本机编译处理

Fastest-lap 固定提交为 `0660208aaeea956c9d833cb32a0ae6b4d959ecb9`，lion 为上游固定的 `e1e4ac06bcbf95e0aeaddcdebabc244e4df08a88`。使用 AppleClang 编译 C/C++，Homebrew GCC 提供 gfortran；CMake 固定在 3.x，避免旧依赖的 CMake 兼容问题。

lion 原脚本追踪 logger-cpp 的 main，该分支已删除它要复制的 `logger.hpp`。构建工具将此依赖固定到仍提供原接口的提交 `94e402b`。保留版本的进度条格式化还使用了 MSVC 专用 `sprintf_s`，构建工具将其替换为带缓冲区长度的标准 `snprintf`。这些处理不修改车辆动力学。其他依赖的实际提交记录在 `docs/upstream-versions.json`，构建工具据此固定依赖。完整编译日志保存在 `runs/build.log`，第三方许可证保留在各上游目录。

## 本机实测

四组网格均成功收敛。120、200、500、1000 点的圈速分别为 59.363、59.889、60.302、60.353 秒，求解耗时约 1.5、2.7、13.2、37.0 秒。500 到 1000 点变化约 0.050 秒（0.083%）；这是一组网格细化检查，尚不是更高精度极限值。1000 点进程峰值内存约 549 MB。

`tools/verify_results.py` 检查真实 IPOPT 成功退出、参数与默认 XML 一致、输出有限、弧长和时间递增，以及采样处参考点的横向边界约束。这里的边界检查针对模型参考点；南京赛道后续仍需按车辆宽度与安全余量处理实际可行驶范围。复现检查：

```sh
.venv/bin/python -m unittest discover -s tests
.venv/bin/python tools/verify_results.py
```

## 200cc / 270cc 配置

`vehicles/presets.json` 保存用户给出的估计功率：200cc 为 4.8 kW，270cc 为 6.3 kW。两者默认车重 100 kg、驾驶员 70 kg，传给 `chassis/mass` 的总质量为 170 kg；最大功率写入单位为 kW 的 `rear-axle/engine/maximum-power`。网页分别提供这三个输入，服务器校验后生成新的车辆 XML，求解结果和存档保留实际参数与预设来源。排量用于配置名称，不额外改变动力学。

这一轮只修改功率和总质量，轮胎、制动、空气阻力、转动惯量和重心仍沿用原模型，因此结果是这组参数下的模型预测。历史上游默认实验保留 165 kg / 20.1 kW；结果区明确显示当前与基准的真实参数，可在相同赛道版本上比较两种车辆的赛车线、速度和累计时间 delta。

南京同一赛道版本、500 点网格实测求解：200cc 为 48.277 s，270cc 为 46.790 s，270cc − 200cc 为 −1.487 s。两组 IPOPT 成功退出，完整赛车线位于图像道路范围内。记录见 `docs/vehicle-comparison.json`。

## Honda 四冲程卡丁车动力模型

卡丁车仍使用刚性后轴 kart-6dof；可选 Honda GX200 / GX270 的发动机净扭矩参考曲线，来源为 Honda 2023 技术资料第 3 页（`vehicles/sources/`），原始链接、人工读图点与拟合误差保存在 `vehicles/engine-curves.json`。GX200 官方净功率 4.3 kW / 3600 rpm，GX270 为 6.3 kW / 3600 rpm。用户 200cc 的 4.8 kW 配置以 GX200 曲线等比例放大，不称为标准 GX200 原厂配置。

原生补丁 `patches/rental-kart-engine.patch` 在自动微分计算中使用三次拟合扭矩曲线，替代恒功率除以轴转速。减速比定义为发动机转速 / 后轴转速，默认 5.0；传动效率默认 0.85，接合转速 1800 rpm、调速器 3600 rpm，均为待校准估计。发动机转速采用后轴同步转速与接合转速的平滑最大值；接合区采用平滑扭矩传递系数（0.35 至 1），表示准稳态滑差，不包含离合器温度、离心机构和发动机瞬态惯量。调速器在设定值附近平滑减扭，因此转速可以略高于设置值；它不是硬转速上限。2000–3600 rpm 之外保持端点扭矩，仍叠加调速器；提高限转不能被解释为已经测得的高转速发动机曲线。

每次求解保存完整曲线、系数、传动和转速设置，并从原生求解器导出发动机 rpm、发动机输出功率、后轴输出功率与车体纵向加速度。输出功率包含当前油门与调速器；后轴功率额外含传动效率和滑差损失。页面提供这些距离曲线及同步游标读数，保留旧恒功率实验供对照；旧实验没有转速数据时不补造数据。全油门参考曲线图显示下一次求解配置的未限转发动机曲线。

500 点求解验证：200cc / 3600 rpm 为 62.553 s、38.812 km/h；270cc / 3600 rpm 为 61.608 s、39.061 km/h；270cc / 3000 rpm 为 72.588 s、33.189 km/h。均按 170 kg、减速比 5、效率 0.85 求解，完整线路与输出功率能量关系通过检查。减速比限制了本组速度，不能将该速度当作实车测量值；降低调速器转速使速度降低、圈速增加。完整数值见 `docs/engine-comparison.json`，复现检查使用 `tools/verify_engine.py`。

## 2026-10-06：统一基线与迭代控制

当前版本用一套 GX200 基础扭矩形状按可编辑功率缩放；200cc / 270cc 为两套参考参数，齿比分别 3.15 / 2.86。上文旧 GX270 独立模型与旧几何成绩为开发历史，当前校准以 `docs/speed-calibration.md` 为准。

原生 Ipopt `intermediate_callback` 使用 `get_curr_iterate(..., scaled=false)` 输出当前优化变量。默认卡丁车导数控制转录每点含 12 个状态（不含时间）、2 个控制与 2 个控制导数，共 16 个变量；保存横向偏移与纵向速度。`src/iterations.py` 使用每次实验的 XML 参考线与法向恢复赛车线。记录可选，静态模式没有车辆标记、距离动画或自动轮次播放。

服务端在独立求解子进程上发送 SIGSTOP / SIGCONT，暂停保留优化器内存状态；记录暂停时长，报告有效求解时间。该实现面向本地 macOS，网页服务仅监听 127.0.0.1。开源安装入口为 `tools/setup.sh` / `tools/start.sh`；仓库不分发上游编译产物、原始地图图像或 Honda PDF。
