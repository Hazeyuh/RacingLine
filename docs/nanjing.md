# 南京引力聚宝山赛道接入

本版本完成图片输入 → 米制几何 → Fastest-lap XML → 默认卡丁车真实求解 → 原图叠加与 delta 比较。地图数据在 `tracks/nanjing/`，原图保留。

## 测量与比赛路径

采用 README 指定的尺度传递方法。卫星图 25 m 比例尺端点为 (26,627)、(127,627)，长度 101 px。主直道按其法线方向在卫星图测量 (548,320) → (553,354)，长度 34.366 px，约 8.506 m；清晰图同处测量 (550,419) → (550,463)，44 px。清晰图尺度为 0.193326 m/px。初始草稿曾量入分隔岛，已修正；旧草稿保存在 `calibration-initial-draft.json`。

卫星图道路边缘模糊，测量端点记为约 ±3 px 的读图不确定性。比例尺准确不等于宽度端点准确；当前尺寸属于图像估计，不是现场测绘。初版参考线长 642.927 m；修正紧弯并平滑参考线后为 618.548 m，不以网络宣传长度校正或进行非线性配准。

起终点放在原图拱架对应的主直道 x=432 px，按 T1 → T17 的顺序行驶，方向由弯号及 T1 箭头推定。排除主直道下方维修道、P 房及左侧 PIT EXIT 支路。比赛方向和现场路线仍可据实修正。

## 当前边界修正与车宽

当前采用 `manual-smooth-v2`。调试期间仅采样点可行但时间倒退的实验已标记无效，不参与比较。左上 T2/T3、中间 T6–T9、右侧 T10/T11 等弯心按原图重新描边，去除颜色/文字噪声造成的突起。`tools/trace_nanjing.py` 保存道路外缘和内缘的人工控制点；红白路肩按草地一侧的边缘描绘，将涂装路肩纳入道路，轮胎墙、隔离墙与维修通道排除。`boundary-trace.json` 保存最终控制点。周期三次样条得到两条平滑闭环；参考线另作周期高斯平滑，消除曲率振荡并保证道路坐标的时间方向有效，检查自交、交叉和参考线包含关系。

每次实验由 `src/nanjing.py` 根据所选车宽生成独立 XML：先对物理道路作欧氏内缩，车宽的一半加每侧 0.10 m 余量，再额外留每侧 0.08 m 网格折线余量。默认车宽 1.4 m 对应求解内缩 0.88 m。法线与同一内缩道路相交得到原生 `nl/nr` 约束；显示边界直接使用内缩后的平滑多边形闭环，在各自弧长上采样，避免法线在紧弯回访同一边界造成画面折返，也不为消除这种坐标折返而收窄实际道路。

网页实线为含路肩的物理道路，虚线为所选车宽的求解参考点范围。总宽输入范围 0.8–2.0 m，仅用于南京赛道；该值影响几何约束，不改变动力学轮距。每次保存车宽、内缩量、物理几何散列与 XML。相同物理几何下允许不同车宽作 delta 比较；旧赛道版本不混入基准。完整赛车线还检查是否位于“半车宽 + 0.10 m”内缩道路内，额外 0.08 m 用于抵消离散线段跨弯角的误差；不合格结果从比较基准中排除。

## 初版几何生成（保留历史说明）

`source.json` 保存人工引导点。周期样条生成参考线，颜色分割识别路面和邻接红白路肩；路肩单独保存为 `kerb-mask.png`。手工墙线限制法线测宽，避免通过轮胎间隙跨到邻接赛道。局部偏移边界发生自交时，只收缩相应区域，直到左右边界各自简单、互不相交且包围参考线。因此这是一条包含识别路肩、局部保守收缩的可用走廊，尚不代表现场全部可用路面。

中间数据采用图片轴（x 向右、y 向下），单位转成米。CSV 的左右按行驶方向定义。XML 用起终点参考点作为局部原点；`metadata.json` 保存像素映射，供原图叠加。KML 是为上游接口准备的合成局部坐标，零纬度不表示南京的实际 GPS 位置。

求解边界每侧另外内缩 0.8 m，对应 1.4 m 横向车宽假设的一半加 0.10 m 安全余量；该假设不改变车辆动力学参数。有效中心点走廊最窄约 1.43 m。`geometry-overlay.png` 展示内缩前保守道路边界，网页和 XML 展示内缩后的求解边界。

上游 Circuit_preprocessor 实际尝试过，因局部不可行退出，日志保留在 `preprocess.log`。最终 `export_nanjing.py` 根据周期样条生成弧长、坐标、航向、曲率、宽度及导数，按真实读取代码的字段导出 XML。已通过实际 C API 读取及求解，不仅是 XML 语法检查。XML 头部的几何误差零值表示解析几何与导出字段一致，不代表图片测量无误差。

## 初版实测与验证（上游默认车辆）

| 网格 | 模型圈速 | 本机求解耗时 |
|---|---:|---:|
| 200 点 | 42.587 s | 4.0 s |
| 500 点 | 44.125 s | 14.6 s |
| 1000 点 | 44.107 s | 57.5 s |

500 到 1000 点的 delta 约 −0.018 s（−0.041%）。200 点不足以稳定解析这些紧弯，其输出采样折线在点间跨出道路约 0.83 m 的线段长度，已标记为粗网格诊断并排除 delta 基准。500/1000 点完整闭环折线均在提取道路内，网页默认使用 500 点。所有结果仍使用上游默认 165 kg、20.1 kW 卡丁车，不是场地实际租赁车辆的预测圈速。

三组 IPOPT 均报告成功。验证包含：闭环、自交、左右边界交叉、参考线包含关系、输出有限性、弧长/时间递增、原生宽度约束以及赛车线采样点在提取道路内；500/1000 点另通过完整闭环折线包含检查。实验各自保存赛道 XML、标定/映射元数据及 SHA-256；网页只提供同赛道且几何版本相同的 delta 基准。

## 重新生成

```sh
.venv/bin/python tools/prepare_nanjing.py
.venv/bin/python tools/export_nanjing.py
.venv/bin/python -m unittest discover -s tests
.venv/bin/python tools/verify_nanjing.py
```

更改 `tracks/calibration.json` 的端点，或 `tools/trace_nanjing.py` 中的边界控制点后，执行前两个命令，再在网页启动新实验。历史实验保留原始赛道快照与原图尺度，不能与新版本直接作 delta 比较。验证记录为 `verification.json`，原图赛车线为 `raceline-overlay.png`。

## 修正版本的车宽对照

同一物理边界版本、Honda GX270 曲线、目标功率 6.3 kW、总质量 170 kg、减速比 5、调速器 3600 rpm、500 点网格：车宽 1.4 m 为 57.741 s，车宽 1.1 m 为 57.417 s；窄车 − 宽车为 −0.324 s。两组时间严格递增，完整赛车线位于各自车宽加 0.10 m 余量的道路范围内。验证程序 `tools/verify_width.py` 检查真实快照、完整闭环、时间方向和显示边界简单性，输出 `docs/width-comparison.json`。该对照验证车宽确实影响优化；1.1 m 仅为对照值，不代表场地车辆实测宽度。
